# MCP источников фидера

Управление набором каналов Telegram-фидера из харнесса: найти канал,
показать пользователю, подключить по коду, переложить, выйти, поставить
доверие, посмотреть отчёт. Спека —
`docs/superpowers/specs/2026-10-23-feeder-mcp-design.md`.

## Где живёт и как включить

Сервер работает **внутри процесса `tg-ingest`**: один токен — один
поллер, второй `TelegramClient` на той же сессии недопустим. Он делит с
раундом свипа один клиент и один замок, поэтому инструмент, которому нужен
телеграм, ждёт конца текущего раунда.

| Что | Как |
|---|---|
| включить | `TG_SOURCES_MCP_PORT=9105` в `.env`, перезапуск `tg-ingest` |
| интерфейс | `TG_SOURCES_MCP_HOST`, по умолчанию `127.0.0.1`; в compose стоит `0.0.0.0` (нужно docker publish), наружу порт выходит только на loopback хоста |
| выключить | пустое значение: сервер не поднимается вовсе, поведение системы прежнее |
| адрес | `http://127.0.0.1:9105/mcp` (Streamable HTTP), публикация только на loopback |
| граф | граф фидера (`KB_GRAPH`, пусто = `default`); заголовок `X-Graph` с другим графом — отказ |
| ключ | Bearer-токен ключа с правом `sources` на этот граф (не `admin`, не `read`/`write`) |
| `KB_MCP_REQUIRE_AUTH=false` | не открывает сервер: инструменты без токена отказывают всегда |

Право `sources` проверяется функцией `authorize`, а не `guard`: `AUTHZ_MODE`
(`off`/`log`) на него не влияет, за инструментом настоящий аккаунт.

## Петля: пробел -> поиск -> список -> код -> подключение

1. Пробел: харнесс видит, что тема не покрыта (`sources_list` — что уже есть).
2. `sources_search(query)` или `sources_resolve(@слаг)` — кандидаты;
   `connected` показывает, что канал уже в реестре.
3. `sources_propose(action="connect", channels=[{peer_id, slug, title, group}])`
   возвращает `proposal_id`, элементы и **одноразовый код**. В телеграм
   ничего не пишется.
4. Харнесс показывает элементы пользователю; пользователь повторяет код.
5. `sources_apply(proposal_id, code)` вступает в канал, кладёт его в папку
   группы, пишет в реестр и подтягивает 100 последних сообщений обычным
   `POST /ingest`.

Аргумент `channels` у `sources_propose`: для `connect` — `[{peer_id, slug, title, group}]`,
для `move` — ровно `[{peer_id, group}]` (`group` — папка назначения), для `leave` —
ровно `[{peer_id}]`.

Предложение живёт около 15 минут, одноразово, и сгорает при любом неверном
коде, коде для другого действия или канала. Перезапуск фидера гасит все
предложения. `move` и `leave` — по одному каналу на предложение.

## Инструменты

| Инструмент | Что делает | Код |
|---|---|---|
| `sources_list()` | подключённые каналы: группа, доверие, `in_folder` (лежит ли канал в своей папке сейчас) и список папок аккаунта | нет |
| `sources_search(query, limit=10)` | поиск публичных каналов | нет |
| `sources_resolve(handle)` | канал по `@слагу` или ссылке; `candidate: null` — не найден | нет |
| `sources_propose(action, channels)` | предложение `connect` / `move` / `leave` и код | выдаёт |
| `sources_apply(proposal_id, code, peer_ids=None)` | подключить (`peer_ids` лишь сужает набор) | да |
| `source_move(proposal_id, code, peer_id)` | переложить в папку, одобренную в предложении | да |
| `source_leave(proposal_id, code, peer_id)` | выйти; строка и принятые документы остаются | да |
| `source_trust_set(peer_id, trust)` | доверие `0..1` или `null` («как у группы») | нет |
| `source_report(peer_id, days=30)` | объём, судьба документов, перепосты, вытеснения, отдача графу | нет |
| `feeder_status()` | курсоры по диалогам, итог последнего раунда (`ok`, при провале `error`), папки и `folders_state` (`fresh` / `stale` / `unavailable`) | нет |

## Правила

- **Доверие действует только вперёд.** Уже записанные связи не
  перештамповываются, переингеста нет. `source_report` — улика для решения,
  решением он не является.
- **Папки агент не создаёт.** Допустимые группы — ровно `GROUP_SET`
  (news, analytics, digest, opinion, official, data); папка должна уже
  существовать в аккаунте. Общий список (chatlist) не правится.
- **Папка при переносе берётся из предложения**, а не из аргумента вызова
  `source_move`: код подтверждает то, что увидел пользователь.
- Один аккаунт = один граф.
- Пустой реестр = прежнее поведение системы.

## Что отвечают ошибки

| Ответ | Причина | Что делать |
|---|---|---|
| «код не принят …» | неверный код, просрочено, уже использовано, код для другого канала или действия | запросить новое предложение |
| «телеграм просит подождать N с» | FloodWait | повторить позже; при `apply` остаток каналов попадает в `skipped` |
| «папки X нет в аккаунте; агент папки не создаёт» | папки нет | создать в клиенте Telegram |
| «папка X — общий список» | chatlist не редактируется | использовать обычную папку |
| «перенос оборвался с неясным состоянием» | канал мог оказаться в обеих папках | повторить перенос: он сходится |
| `forbidden: sources not allowed` | у ключа нет права `sources` | выдать ключ с правом на граф фидера |
| `authentication required` | вызов без токена | передать Bearer |

## Не пришло уведомление / канал молчит — где смотреть

| Симптом | Где смотреть |
|---|---|
| канал подключён, документов нет | `feeder_status`: курсор диалога (`last_id`) и `last_round.tally` (`failed`, `dialog_errors`) |
| канал есть в реестре, но свип его не видит | `sources_list`: `in_folder=false` — канал убрали из папки руками; вернуть в клиенте или перенести `source_move` |
| раунд долго не заканчивается | `feeder_status` отвечает без замка: курсоры и `last_round` есть всегда, `folders_state` = `stale`/`unavailable` значит раунд держит замок; смотреть лог `tg_ingest sync round` |
| `last_round` пуст, а фидер только что перезапустился | раунд упал: исключение пробрасывается наружу, процесс выходит, `restart: unless-stopped` поднимает контейнер. Причина — только в логе `tg-ingest` (строка раунда), в `feeder_status` она не доживает |
| `last_round` пуст | первый раунд ещё не завершён (после рестарта) |
| документы приняты, а в графе пусто | `source_report`: `fate` (completed/failed/skipped), `origin` (перепосты не дают новых связей) |
| уведомления подписки не приходят | это контур наблюдения, не источники: [`watch.md`](watch.md) |
| сервер не отвечает | в логе `tg-ingest` строка «MCP источников упал»: свип при этом продолжает работу (в том числе при занятом порте: uvicorn выходит через `SystemExit`, хостинг его ловит); причина — порт занят или нет Postgres |
