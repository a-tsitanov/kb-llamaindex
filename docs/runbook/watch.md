# Наблюдение за сущностями: подписки, события, доставка

Контур — `src/watch/`. Одна дуга: подписки в Postgres, события в
`watch_event`, из них и лента, и рассылка. Прежняя дуга `:Alert` в Nebula
выведена (см. «Что исчезло» ниже).

## Как это работает

| Шаг | Где | Что происходит |
|---|---|---|
| Подписка | MCP `kb_watch` | строка в `watch`: владелец, сущность, виды событий, адресат доставки |
| Журналы | ингест (`src/watch/journal.py`) | каждый документ дописывает `entity_mention` и `edge_new` |
| Свип | активность `sweep_watch`, раз в `MONITOR_SWEEP_INTERVAL_MINUTES` | журналы за своими курсорами + рост `risk_score` → `watch_event` |
| Лента | MCP `kb_watch_feed` / `kb_ack` | чтение и отметка прочтения (`watch_seen`) |
| Доставка | активность `deliver_watch`, тем же проходом после свипа | `watch_event` → webhook подписки (`watch_delivery`) |

Виды событий: `new_mention`, `new_connection`, `new_identifier`,
`new_event`, `contradiction`, `risk_rise`. `kinds` у подписки сужает
набор, пусто = все.

Событие несёт **провенанс приёма** в `detail.provenance`: источник
(`source_kind` — имя ключа, которым документ принесли), вердикт приёма и
ссылка на владельца тела. Это и есть ответ на «новая связь — из
первоисточника или из перепоста»: по графу они неразличимы.

## Доставка

Включается адресатом НА ПОДПИСКЕ — не одним URL на установку:

```
kb_watch(name="Акме", webhook_url="https://hooks.example/kb")
```

Пустой `webhook_url` = только лента (и это же способ доставку отключить:
повторная подписка адресат перезаписывает).

| Свойство | Поведение |
|---|---|
| Дедуп | ключ `(owner, event_id)` в `watch_delivery`: одно событие одному подписчику уходит один раз, сколько бы раз свип ни перезапускался |
| Повтор | неудача помечается `failed`; следующий проход свипа и есть расписание повтора, до 3 попыток. Отдельной очереди ретраев нет |
| Потолок | `MONITOR_DAILY_PUSH_LIMIT` (20) на подписку в сутки; колонка `watch.daily_push_limit` переопределяет. Остаток — одной сводкой (`watch_digest`), сводки в потолок не считаются |
| Право | перед КАЖДОЙ отправкой: у ключа, которым подписались (`watch.created_by`), должно быть право `read` на этот граф. Отозвали все ключи этого имени — рассылка молчит, события остаются неотправленными |
| Подписка без ключа | `created_by` пусто (легаси-строка или stdio без токена) — только лента. `kb_watch` с `webhook_url` без токена отказывает сразу, чтобы не создавать молча недоставляемую подписку |
| Адресат | только `http`/`https`, проверяется и при записи подписки, и при отправке |
| `AUTHZ_MODE` | на доставку НЕ влияет: режим `log` пропускает запрос ради окна наблюдения, а здесь «пропустить» значит отправить содержимое графа наружу |

Тело одного события: `graph`, `event_id`, `kind`, `entity{vid,name}`,
`doc_id`, `doc_date`, `why`, `detail` (с провенансом), `detected_at`,
`document_url`. Тело сводки: `digest: true`, `suppressed`, `by_kind`,
`entities`, `from`/`to`, `reason`.

## Что смотреть, когда «уведомления не приходят»

| Симптом | Где смотреть |
|---|---|
| в ленте пусто | `monitor_cursor` (двигается ли свип), `MONITOR_ENABLED`, пул `monitor` у воркера |
| в ленте есть, пушей нет | `watch.webhook_url` пуст? `watch_delivery` — есть ли строки и с каким `state` |
| `state = 'failed'` | `last_error` в той же строке; `attempts` ≥ 3 означает, что повторов больше не будет |
| строк в `watch_delivery` нет вовсе | отказ в праве или адресате: в логе воркера `watch delivery refused` с `created_by` либо `url` |
| пришла одна сводка вместо событий | сработал суточный потолок; полный список — в ленте |
| событие старше подписки | так и задумано: `watch_event.detected_at >= watch.created_at`, история не досылается |

Разовый проход, не дожидаясь расписания:

```bash
curl -X POST -H "X-API-Key: $API_KEY" http://localhost:8000/admin/monitor/sweep
```

## Что исчезло вместе с дугой `:Alert`

Узлы `:Alert`, активности `detect_alerts`/`deliver_alerts`, флаг
`Entity.watched`, маршрут `POST /admin/monitor/watch`, переменные
`MONITOR_WEBHOOK_URL`, `MONITOR_NEW_WINDOW_DAYS`, `MONITOR_BURST_*` и
аналитический примитив `alerts`.

Причина: `new_connection` порождали ОБЕ дуги, то есть «одно уведомление
на событие» при них было недостижимо. Из дуги сохранён один детектор,
`risk_rise`; burst-детектор под nebula не был портирован вовсе и ушёл в
`docs/BACKLOG.md`.

Узлы `:Alert`, уже записанные в граф, остаются мусором — код их больше не
читает и не пишет. Чистка операторская, при необходимости:
`MATCH (a:Alert) DETACH DELETE a` в Studio.

## Выкат

Воркер (пул `monitor`) обязан подняться с новым кодом: активность
`deliver_watch` новая, а `detect_alerts`/`deliver_alerts` больше нет —
старое расписание, нашедшее их по имени, получит «activity not
registered». Само расписание не меняется: имя воркфлоу
(`MonitorSweepWorkflow`) сохранено намеренно.

Схема: `scripts/setup_db.py` добавляет `watch.webhook_url`,
`watch.daily_push_limit`, таблицы `watch_digest` и `watch_delivery`
(идемпотентно, как остальной `GRAPH_DDL`).
